\section{Simulation Results}

To complement this mathematical approach, we also computed simulations tracking performance on quantum algorithms as we varied temperature as the single control parameter. We computed simulations of both:
\begin{itemize}[itemsep=1pt]
	\item Full quantum circuits, tracking full density matrix representations, allowing us to employ full Qiskit noise models
	\item Circuits using only Clifford gates, tracking qubit state using stabiliser states and only employing simpler Pauli noise models. This allowed us to simulate much larger numbers of qubits.
\end{itemize}

\subsection{Preface of Result Validity}

The validity of these results hinges primarily upon the correctness of the code used to generate them. Thus, we have generated an extensive suite of unit tests to ensure the framework is operating as expected.

Moreover, the validity and applicability of these results further hinges upon the use of correct and properly catalogued assumptions used to generate them. We employ the following to mitigate the risks of compromising these qualities:
\begin{itemize}[itemsep=1pt]
	\item The use of a variety of different methods of producing results, including a variety of different metrics and methods of generating noise models. These methods vary in complexity and specificity, avoiding how many assumptions are universally relied upon.
	\item Comprehensively cataloguing the assumptions used at every stage of generating the results, including how they change for each method of producing results.
\end{itemize}

To do this, we treat each set of results as a case study. Because there is so much overlap between the assumptions of each case study, we include a set of all set of assumptions in the appendix, and specify which ones apply for each.

There are a few assumptions that due to the inherent limitations of the simulation architecture universally apply, and are worth pointing out separately:

\begin{itemize}
	\item All noise models are inherently gate-local (and thus also qubit-local)
	\item All noise models are state independent and unchanging over time throughout the whole metric simulation, and every shot and trial of the metric
	\item All noise models are Markovian
\end{itemize}

For all further assumptions, reference specific assumption sets on a per case study basis. The theory behind some of the assumptions is listed in the third subsection.

\subsubsection{Hardware Parameters}

I make the following modelling assumptions for the IBM processors:

All data mentioned below is IBM calibration data pulled directly from the latest github commit.

We use the following hardware parameters in the temperature dependent model:
\begin{itemize}
	\item $\gamma_0$ is fit at runtime
	      \begin{itemize}
		      \item It is calculated by minimising the squared error between the estimated and actual T1 values, keeping all other model parameters constant
		      \item To produce the estimated T1 values, we assume such data is generated at the default operational MXC temperature, which is taken as 0.013K
		      \item To retain per-qubit accuracy, we calculate and store the multiplicative error of each qubit's T1 value at the operational temperature, and adjust all estimates for T1 values at other temperatures with this multiplicative factor
		      \item An improvement for future builder classes would be to store a value for $\gamma_0$ on a per qubit basis instead of averaging
	      \end{itemize}
	\item $\gamma_{\varphi-\text{base}}$ is fit at runtime
	      \begin{itemize}
		      \item It is calculated by minimising the squared error between the estimated and actual T2 values, keeping all other model parameters constant
		      \item This is calculated after estimating $gamma_0$
		      \item We assume such data is generated at operational MXC temperature, which is taken as 0.013K
		      \item As before, to retain per-qubit accuracy we calculate and store the multiplicative error of each qubit's T2 value at the operational temperature and adjust all estimates for T2 values at other temperatures with this multiplicative factor
		      \item An improvement for future builder classes would be to store a value for $\gamma_{\varphi-\text{base}}$ on a per qubit basis instead of averaging
	      \end{itemize}
	\item $\frac{\gamma_{MXC}}{\gamma_0}$ is estimated as $0.9$
	      \begin{itemize}
		      \item The maximum value from the experimental dataset reported in Ref.~\cite{lvov2025thermometry} is 0.85.
		      \item We can assume this is using standard lab equipment, making 0.9 a lower bound for professional IBM architecture
	      \end{itemize}
	\item $T_{env}$ is fit at runtime
	      \begin{itemize}
		      \item It is calculated by estimating a value for each qubit and taking the median
		      \item prob\_meas1\_prep0 is extracted for each qubit, and used alongside previously estimated parameters and equations from ~\cite{lvov2025thermometry} to estimate $T_env$, as described in Section~\ref{sec:T_env-estimation}
	      \end{itemize}
	\item $\Delta$ (superconducting energy gap) of $50,000$
	      \begin{itemize}
		      \item This is the known value for Aluminium, which we can assume the electrodes used in IBM transmon qubits are made of
	      \end{itemize}
	\item Subgap Transparency is set at 0.00005
	\item $R_n$, or normal state resistance, is set at 5000
	\item $\omega_{ge}$ is extracted from known configuration data for each backend individually for each qubit
	\item $N_e$, the number of effective channels in the Josephson Junction, is estimated at $1.29\times10^{5}$. We calculate this value using:
	      \begin{itemize}
		      \item An estimated normal resistance of the Josephson Junction of $5\text{k}\Omega$
		      \item Transparency of the junction in the subgap regime of $5\times10^{-5}$
	      \end{itemize}
	\item $E_c$, charging energy of the capacitors in the transmon qubits, of $0.95\mu$eV
	\item $E_j$, josephson energy of the transmon qubits, of $62.1\mu$eV
\end{itemize}

When calculating gate errors, the difference between the known gate error and calculated gate error at the operational temperature is stored and assumed to be
representative of the non-thermal error, and thus independent of temperature. It is then added to future calculated gate errors

\subsection{Theory}

\label{sec:T_env-estimation}
$T_env$ is calculated in the Default Builder using the following pathway:
\begin{itemize}
	\item First the probability of measuring $\ket{1}$ after preparing $\ket{0}$ is extracted for each qubit
	\item The residual excited state population, $p_e$, as estimated as equal to this value.
	\item The number of effective thermal photons is estimated using from the Bose-Einstein distribution and assumption of normalisation ($p_e + p_g = 1$):
	      \[
		      n_{\text{eff}} = \frac{p_e}{1 - 2*p_e}
	      \]
	\item Following the two-bath model of Ref.~\cite{lvov2025thermometry}, $n_{\text{eff}}$ is given by [Eq.~(14)]:
	      \[
		      n_\text{eff} = \frac{\gamma_\text{MXC}}{\gamma_1^0} n(\omega_{ge}, T_\text{MXC}) + \frac{\gamma_\text{env}}{\gamma_1^0} n(\omega_{ge}, T_\text{env})
	      \]
	\item Now, taking $n(\omega_{ge}, T_\text{MXC})$ to be negligible and rearranging for $T_{\text{env}}$ we get:
	      \[
		      T_\text{env} = \frac{\hbar\omega_{ge}}{k_B \ln\!\left(1 + \frac{\gamma_\text{env}}{\gamma_1\,n_\text{eff}}\right)}
	      \]
	\item We can then use qubit specific values of $\omega_{ge}$, and the $\gamma_1$ term cancels out
\end{itemize}

Note that this is an upper bound, and thus safely overestimates noise.
